# W1 initializer and quotation identity boundary

W1 repairs all four core initializer export mismatches (**85/85**) and the
M17 `register_label_attr` mismatch. They were association errors, so no kernel
literal normalization was needed. The remaining 21 relocated exports contain
different literal data: 20 M17 simp-attribute groups and one M08 quotation.
Their exact IDs remain rejected. This limits the identity claim to groups
whose complete re-encoding verifies; it does not claim that arbitrary
observable module names can be erased soundly.

The historical P1/Fork G4 result was **1116/1142 exact exported declaration-group IDs**. The other 26 groups built, but their re-encoded `.olean` declarations did not equal the stored group IDs. Four of those 26 were core fixtures (`81/85`), and 22 were Mathlib groups. The inventory below describes that frozen baseline; IDs in its logs are prefixes specific to that base and encoding version.

The F13 mismatch reproduced with **no module relocation**: recapturing and exporting only `Fixtures.F13InitDecl` under the same name gave `0/3` exact IDs. Captured command order was `IO.Ref` (hygiene hash `3351517196`), trace class (`386426778`), option (`3136702651`); the built `.olean` listed those initializer constants as trace, option, ref. `Lean.Environment.exportModuleData` sorts exported constants by name, while the old `exportIdentity` popped that list in capture order. Every F13 initializer was therefore paired with the wrong constant. The corrected lookup compares captured and exported raw hygiene keys: user name, command hash, imported scopes, context, and numeric scope ordinals, rebasing only the current module prefix. It requires a single candidate and forbids assigning one exported constant twice. It still re-encodes that constant and compares the full group ID exactly. A rebuilt P1 exporter verifies **3/3** F13 IDs from the preserved capture. [ExportLookup.lean](../impl/p1/tests/ExportLookup.lean) checks the key association and duplicate-use rejection against that actual `.olean`; [ExportLookupAmbiguous.lean](../impl/p1/tests/ExportLookupAmbiguous.lean) generates two distinct constants with one raw key and requires rejection. Private copied-source mutations of the singleton and reuse guards make their respective executable tests fail; [the mutation runner](../impl/p1/scripts/check-export-lookup-mutations.sh) reproduces both failures without editing production source.

F10 is a second association error, with a different cause. Its captured generated initializer scopes are `5,22`; the stock-built export has `5,28` under the **same command hash**. Forcing the `22→28` association in a test while leaving group encoding untouched produced the stored exact ID `04043f8c56590724dac5541fb14bfc763bc7639f61e558590a6622ddb8aafff0`. The refined lookup computes every exported full-key reservation and residual capture count before assignment, then permits a scope-ordinal residual association only when exactly one unmatched captured member and one unclaimed exported member have the same remaining hygiene key. Full-key ambiguity, residual ambiguity, and duplicate assignment fail closed. The final stock core recheck against unchanged built `.olean`s is **85/85**; fork core was already **85/85** after the first repair. [ExportLookupResidual.tla](../verification/tla/ExportLookupResidual.tla) models this reservation and the unchanged content comparison. TLC explores 1,040 states; eight base reachability witnesses and four base guard-removal mutations include a failed exact owner, an ambiguous exact owner, and a changed body. A derived temporary variant adds a third unclaimed exported candidate to the ambiguous owner's stem; the variant passes, while removing only the no-full-key fallback guard admits the ambiguous owner and violates `NoAmbiguousAccepted`. [The executable fixture](../impl/p1/tests/ExportLookupResidualCheck.lean) and [mutation runner](../impl/p1/scripts/check-export-lookup-residual-mutations.sh) test the same case and four source guard removals against a real generated `.olean`.

The remaining M17 failures have concrete encoded-content evidence. With every member associated under the final lookup, [the read-only dumper](../impl/p1/tests/DumpExistingExportGroup.lean) re-encoded all 21 groups from existing stock and fork `.olean`s and compared them with the captured group objects. For each of the **20 `register_simp_attr` lines** listed above in both toolchains, the canonical name, reference, and level sections are byte-identical, while the expression section grows from 174 to 179 entries and gains one actual `Expr.lit (.strVal "ParaleanExport")` absent at capture. The captured expression literals include `_@`, `Mathlib`, `Tactic`, and `Register`; the exported literals insert `ParaleanExport` after `Mathlib`. Each full encoding grows 34 bytes and has a different ID. The line-102 `register_label_attr` group is byte-identical. The [stock](../impl/p1/results/w1-identity/m17-encoded-diff.tsv) and [fork](../impl/p1/results/w1-identity/m17-fork-encoded-diff.tsv) per-line tables record all 21 full IDs and section comparisons; [the section parser](../impl/p1/scripts/summarize-export-group-diff.py) decodes expression tags to distinguish literal strings from other bytes. M08 line 37 likewise has equal name/reference/level sections in both toolchains, but its expression section grows from 409 to 412 entries, gains the same literal after `_private`, and changes the exact ID; see the [stock](../impl/p1/results/w1-identity/m08-encoded-diff.tsv) and [fork](../impl/p1/results/w1-identity/m08-fork-encoded-diff.tsv) artifact rows. These measurements establish the current relocated export's content difference for these groups. They do not rule out a separately proved, semantics-specific handling of a restricted initializer or quotation.

## Why a name quotient is insufficient

P1's `normName` normalizes **declaration and reference names** (private prefixes, relocation components, macro-scope tails) in [Model.lean](../impl/p1/Paralean/Model.lean). Scoped member spellings are metadata outside the group hash. An `Expr.lit (.strVal s)` in a **kernel value** is encoded verbatim in [Encode.lean](../impl/p1/Paralean/Encode.lean). Lean represents a quoted `Name` with string components in that value, and an initializer or macro can inspect the resulting `Name`. Replacing one module component inside that data with a common symbol could make unequal bodies share an ID while their runtime behavior still distinguishes the modules. Capture's current diagnostic searches only for `_private` or `_@` string literals ([Capture.lean](../impl/p1/Paralean/Capture.lean)). It detects the F13 trace-class body at line 8. A two-module dump of the named F13 IO.Ref and option initializer bodies found no module-sensitive string literal there. Their corrected same-module export verifies exactly, so their baseline mismatches were caused by lookup order. The trace-class body also verifies exactly in its original module; relocation can still change its literal, and the full group ID must decide that case.

A minimal executable witness uses the same `register_simp_attr identity_simps` command in [IdentityOriginal.lean](../verification/fixtures/identity/IdentityOriginal.lean) and [IdentityRelocated.lean](../verification/fixtures/identity/IdentityRelocated.lean). On the fork at `99967f1` with `LEAN_PARALEAN=1`, `bash scripts/check-identity-fixture.sh .runs/w1/toolchains/fork-stage1/bin/lean` passes and prints these generated members and embedded string values:

```text
_private.verification.fixtures.identity.IdentityOriginal.0.initFn._@.verification.fixtures.identity.IdentityOriginal.1111279983._hygCtx._hyg.28: [IdentityOriginal]
_private.verification.fixtures.identity.IdentityOriginal.0.initFn._@.verification.fixtures.identity.IdentityOriginal.1111279983._hygCtx._hyg.5: [IdentityOriginal]
_private.verification.fixtures.identity.IdentityRelocated.0.initFn._@.verification.fixtures.identity.IdentityRelocated.1111279983._hygCtx._hyg.28: [IdentityRelocated]
_private.verification.fixtures.identity.IdentityRelocated.0.initFn._@.verification.fixtures.identity.IdentityRelocated.1111279983._hygCtx._hyg.5: [IdentityRelocated]
PASS: generated initializer literals differ with the Lean module
```

[InitializerIdentity.lean](../verification/veil/Paralean/InitializerIdentity.lean) proves the limited fact needed here: group-keyed rendering of a scoped declaration can remain equal across module relocation while its embedded private-name value changes; any quotient that identifies those two values fails to reflect exact observable equality. This is an abstract refinement of the name distinction, not a proof about all Lean elaborator expansions or cryptographic collision resistance. It does not exclude a semantics-specific normalization for a restricted metaprogram after separately proving that its name data cannot affect behavior.

[ReplayIdentity.tla](../verification/tla/ReplayIdentity.tla) models context selection before replay. A module-sensitive group is accepted in its original context and rejected in a synthetic context; an ordinary group is accepted in either. `AcceptedExact` independently checks the output against stored content. TLC explores 16 distinct states with no error; three witness runs establish the useful paths, and removing the exact acceptance guard produces an `AcceptedExact` counterexample. The model is finite and abstracts the actual group bytes and elaborator; it tests the protocol rule, not a claim that every original-context elaboration succeeds.

[ExportLookup.tla](../verification/tla/ExportLookup.tla) separately models sorted `.olean` order, unique raw-key lookup, one-to-one assignment, and unchanged exact-body comparison. TLC explores 160 distinct states without error. Reachability witnesses show all three reordered F13 groups accepted, while changed literal content, ambiguous candidate keys, and reused candidates are rejected. Removing the raw-key, singleton, one-to-one, or exact-body guard yields a counterexample. This finite model abstracts Lean's `Name` representation; the executable F13 test supplies the concrete correspondence. The residual model reserves every full-key candidate before validation, even if its owner later fails or has an ambiguous full key. The implementation additionally marks an associated candidate used during lookup, so its reuse rule is stricter after a later body failure.

For groups checked by source replay, acceptance requires exact stored identity. Materialized initializer coverage is a separate existing mechanism for consumer effects; it does not prove byte-identical re-elaboration or exported literal-body identity. W1's targeted M08 replay now passes a cold `check-group` under the stored source module while retaining the exact group-ID comparison. That repairs the historic M08 source-replay failure documented in [m-targets-log.md](m-targets-log.md) for this targeted check; wider mixed-module closures still need their own measurement. The `1116/1142` result is the frozen baseline. The repairs account for four core groups and one M17 group; the current relocated export still rejects the 20 M17 initializer groups and the M08 quotation by exact content.
