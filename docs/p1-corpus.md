# P1 extraction corpus

Owner: P0. This fixes the corpus against which P1 (local declaration replay and stock
export, [plan](plan.md#p1--local-declaration-replay-and-stock-export)) is measured.
Formats and name classes are those of [p0-interfaces.md](p0-interfaces.md).
The pins are Lean `193c3589` and Mathlib `0575336`; the stock reference binary is
`~/p0-deps/lean-stock-193c3589`.

The corpus has four parts:

1. **Core fixtures** `corpus/fixtures/Fixtures/F01…F15`: a stock-Lean Lake package
   (no Mathlib), one fixture family per declaration kind P1 must handle.
2. **Cross-workspace fixture** F14: `corpus/fixtures/crossws/` (agent view, with
   cyclic file imports) and `Fixtures/F14/{B1,A,B2}.lean` (expected acyclic export).
3. **Mathlib fixture** F16 (`corpus/mathlib-fixtures/`) and **18 fixed Mathlib
   modules** M01–M18 (`corpus/modules.txt`).
4. **Negative fixtures** N1–N6 (`corpus/fixtures/negative/`), which must be rejected.

`bash corpus/run-oracle.sh` regenerates the reference data in `corpus/reference/`.
The reference oracle `corpus/tools/CommandDecls.lean` elaborates each file command by
command with stock Lean (`Elab.async=false`). For each command it records the
constants added (with Lean's *spelling* name class), the source byte length, and the
persistent-extension entry deltas. It is the expected behaviour P1 must reproduce,
not an implementation of capture.

## Mathlib modules

The modules are fixed in `corpus/modules.txt` (M01–M18), at Mathlib `0575336`. They
were chosen to cover every feature above at Mathlib scale: classes and
`to_additive` (M02, M10), structural and WF recursion (M03–M05, M14), scoped notation
(M03, M06), `initialize` and `register_simp_attr` (M07, M17), macros (M08), `simps`
(M09), deriving (M11), private declarations (M12, M16, M18), class hierarchies (M13),
mutual inductives (M15), and plain theorem-heavy files (M01, M16, M18). For module
`Mi` the replay/export **base** is `Mi`'s transitive import closure from the pinned
local build, without `Mi` itself.

## Gates

All gates are measured by P1 against the reference data above. The numeric
thresholds are set at P0. Changing one requires an entry in p1-log.md with the
measured distribution that motivates it.

**G1. Replay success rate.** A group passes if replaying its capsule in a fresh
process (base + store-materialized deps, stock kernel, `Elab.async=false`) reproduces
its interface (p0-interfaces.md §5): names, classes, types, non-`Prop` def values,
deps and effects. It must also pass the kernel.
- Fixtures F01–F16: **101/101 groups (100 %)**.
- Mathlib M01–M18: **≥ 98 % of 1,046 groups**. **Every** non-passing group carries an
  explicit unsupported-extraction diagnostic (0 silent mismatches).
- Also reported: the exact group-ID match rate, and the replay-time / oracle-time
  ratio.

**G2. Membership and name classes.** For every command, the published public-name set
equals the oracle's `public` set **after** these provenance corrections:
auto-named instances and deriving outputs (F08, F09, F03 `instRepr*`, F11) move to
scoped-generated; everything created by `realizeConst` but not spelled reserved
(`_unary.induct` in F07, and the realized `_arg_pusher` auxiliaries, which are
scoped realized auxiliaries in P1's terms) moves out of the published members. The
oracle's `reserved` column, which already includes the private-spelled
`match_n.eq_n`/`splitter`, is never published. Required: 0 reserved names published, 0 commands
split across groups, 0 groups spanning two commands, and every group without a public
name has exactly one anchor.

**G3. Capsule size** (PCE bytes of the capsule body, excluding `requires` targets,
which are counted once each; ratio = capsule bytes ÷ the command's oracle `bytes`):
- Fixtures: every capsule ≤ 4 KiB; per file, total capsule bytes ≤ 6 × total source
  bytes.
- Mathlib: per group, p50 ratio ≤ 4 and p95 ≤ 16; every capsule ≤ 64 KiB; per module,
  total capsule bytes ≤ 6 × module source bytes (reference total 243,082 B →
  ≤ 1.46 MB).
- Every group above the p95 bound is listed with its cause ("cases requiring larger
  source capsules", plan P1).

**G4. Export build success.** Each fixture family, and each Mathlib module's groups,
are exported from the store into a clean directory and built with the frozen stock
binary `~/p0-deps/lean-stock-193c3589/bin/lake` (no fork, no runtime, no cache):
- **21/21 fixture files** (F14 as an acyclic layout of ≥ 3 files) and **18/18
  Mathlib modules** build with exit 0.
- For every public member, the built constant's type equals the reference.
  `#print axioms` sets equal the oracle build's. Source/line mappings resolve for
  100 % of diagnostics.

**G5. Negatives.** 6/6 rejected with the stated reasons; 0 receipts issued; 0 groups
staged.

**G6. B→A→B.** (a) B's capture of `helper_c` before A publishes `helper` fails with
"unknown dependency": `helper_c` stays a private draft and no group is published.
(b) After A publishes `helper` (pinning B's `helper_b` group ID), B captures
`helper_c`, whose dependency map pins A's group ID. (c) The export has acyclic
imports, at least 3 files, builds under G4, and the chain `helper_c → helper →
helper_b` is checked by group IDs, not names. A model or implementation that
rejects dependent declarations must fail this gate.
